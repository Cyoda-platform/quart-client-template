# Customer Management API - Functional Requirements

## Overview
A REST API to manage customers with full CRUD capabilities. Endpoints should include create, read (by id), update, delete, and list with pagination, filtering, and sorting.

## Entities
- Customer:
  - id (string) - unique identifier
  - name (string) - customer name
  - email (string) - contact email
  - phone (string) - contact phone
  - address (object) - street, city, state, zip
  - metadata (object) - free-form key/value for extensibility
  - created_at (string - ISO8601)

## API Endpoints
- POST /customers
  - Creates a new customer. Request: Customer payload without id and created_at. Response: Customer with id and created_at.
- GET /customers/{id}
  - Returns customer by id.
- PUT /customers/{id}
  - Replaces the customer record.
- PATCH /customers/{id}
  - Partial updates customer fields.
- DELETE /customers/{id}
  - Soft deletes the customer (marks as deleted via CustomerManagement workflow).
- GET /customers
  - Lists customers with query parameters: page, size, sort, search, filter (by email, name)

## Validation & Behavior
- email must be valid format, unique.
- name required, non-empty.
- phone optional but normalized if provided.
- created_at generated by server.
- Soft delete: set a 'deleted' flag and move workflow state to 'deleted'.

## Non-functional
- Pagination default page=0 size=20, max size=100.
- Responses use JSON:API style simplified: {"data": {...}, "meta": {...}}

## Security
- API secured with token-based auth (implementation choice during deployment).

## Notes
- Integrate with CustomerManagement workflow to move states on create/update/delete.
