# Customer Management - Functional Requirements

Overview
--------
This service manages Customer records and exposes a REST API for CRUD operations. It will be implemented in Python and provide endpoints for create, read (list & detail), update, and delete customers.

Primary goals
-------------
- Reliable CRUD operations for Customer entities
- Input validation and clear error responses
- Pagination for list endpoints
- Basic search/filtering by name and email
- Idempotent updates and safe deletes
- Open to future workflow integration (e.g., verification, archival)

Customer Entity (concrete example)
----------------------------------
{
  "id": "cst_001",
  "firstName": "Alice",
  "lastName": "Johnson",
  "email": "alice.johnson@example.com",
  "phone": "+1-555-123-4567",
  "address": {
    "line1": "123 Main St",
    "line2": "Apt 4",
    "city": "Springfield",
    "state": "IL",
    "postalCode": "62704",
    "country": "US"
  },
  "status": "active",
  "createdAt": "2026-01-05T12:00:00Z",
  "updatedAt": "2026-01-05T12:00:00Z"
}

Fields & Validation
-------------------
- id: string, unique, generated by server (e.g., cst_uuid)
- firstName: string, required, max 50 chars
- lastName: string, required, max 50 chars
- email: string, required, valid email format, unique
- phone: string, optional, E.164 recommended
- address: object, optional; when present, line1, city, postalCode, country required
- status: enum [active, inactive, archived], default: active
- createdAt / updatedAt: ISO-8601 timestamps (server-generated)

REST Endpoints
--------------
Base path: /api/v1/customers

1) Create Customer
- POST /api/v1/customers
- Request body: Customer object without id, createdAt, updatedAt
- Response: 201 Created
  - Body: created Customer object with id and timestamps
  - Location header: /api/v1/customers/{id}
- Errors: 400 (validation), 409 (email conflict)

2) List Customers
- GET /api/v1/customers
- Query params:
  - page (int, default 1)
  - per_page (int, default 20, max 100)
  - search (string) -> searches firstName/lastName/email
  - status (filter)
- Response: 200 OK
  - Body: {"items": [Customer], "page": 1, "per_page": 20, "total": 123}

3) Get Customer by ID
- GET /api/v1/customers/{id}
- Response: 200 OK (Customer) or 404 Not Found

4) Update Customer
- PUT /api/v1/customers/{id}
- Request body: Customer fields to replace or full upsert semantics (choose replace semantics)
- Response: 200 OK (updated Customer) or 404 Not Found or 409 Conflict
- Partial updates could be supported via PATCH in future

5) Delete Customer
- DELETE /api/v1/customers/{id}
- Response: 204 No Content or 404 Not Found
- Soft delete recommended (status=archived) with hard delete as admin-only option

Error Handling
--------------
- Standardized error response:
  {
    "error": {
      "code": "validation_error",
      "message": "Email is invalid",
      "details": {"email": "invalid format"}
    }
  }
- Use appropriate HTTP status codes (400, 401, 403, 404, 409, 500)

Security
--------
- API key or token-based auth (implementation detail)
- All endpoints require authentication except for health checks
- Rate limiting and logging are out-of-scope for initial build but should be considered

Acceptance Criteria
-------------------
- All CRUD endpoints implemented and cover happy-path and error cases
- Input validation enforced and tested
- Unique constraint on email enforced at persistence layer
- List endpoint supports pagination and search
- Unit tests for service layer and API tests for endpoints

Sample Requests
---------------
Create:
curl -X POST "http://localhost:8080/api/v1/customers" -H "Content-Type: application/json" -d '{"firstName":"Alice","lastName":"Johnson","email":"alice.johnson@example.com"}'

Get list:
curl "http://localhost:8080/api/v1/customers?page=1&per_page=20&search=alice"

Get by id:
curl "http://localhost:8080/api/v1/customers/cst_001"

Update:
curl -X PUT "http://localhost:8080/api/v1/customers/cst_001" -H "Content-Type: application/json" -d '{"firstName":"Alicia","lastName":"Johnson","email":"alice.johnson@example.com"}'

Delete:
curl -X DELETE "http://localhost:8080/api/v1/customers/cst_001"
