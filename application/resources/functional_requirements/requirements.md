## Key Workflows (high-level)
- Order Processing
  - Trigger: Order created
  - Steps: validate order -> reserve inventory -> charge payment -> mark order as confirmed -> notify user

- Customer Onboarding
  - Trigger: Customer created
  - Steps: validate email -> send welcome email -> create initial profile tasks

## APIs / Routes
- POST /orders -> create a new Order (publishes Order.created event)
- GET /orders/{id} -> retrieve order
- POST /customers -> create Customer

## Processors
- PaymentProcessor: handles charging payments and retries on transient failures
- NotificationProcessor: sends emails or pushes notifications after key state transitions

## Non-functional Requirements
- Idempotent event processing
- At-least-once delivery for critical processors with retry/backoff
- Observability: structured logging and metrics for processors and workflows
- Config-driven timeouts and retry policies

## Acceptance Criteria
- End-to-end order creation triggers the Order Processing workflow and results in an order in confirmed state when payment succeeds.
- Entities have example JSON instances and pass basic schema validations in Canvas.
- Workflows validate against the Cyoda workflow schema.
